# Как работать с репозиторием

## Ветки и слияние

- В `main` код попадает только через PR. Прямой push отклоняет хук `pre-push`, force-push запрещён.
- Ветка называется `<имя>/<тема>` и создаётся от свежего `main`: `vladislav/llm-gateway`. Одна ветка — одна задача; найденную по дороге постороннюю правку выносим в отдельный PR.
- PR сливается со сжатием коммитов (squash), когда зелёный CI на текущем head, есть просмотр вторым участником и согласие владельца задачи. Пары для просмотра: роли 1 и 2, роли 3 и 4.
- После слияния синхронизируем `main`: `git merge --ff-only origin/main`.

## Коммиты

Заголовок: `область: что сделано`, по-русски, до 72 символов, без точки на конце.

```
llm: резерв модели при таймауте
agent: проверки V2–V4
```

- Область — латиницей: `repo`, `contract`, `db`, `api`, `agent`, `llm`, `clients`, `rank`, `news`, `text`, `ci`, `deploy`, `docs`, `config`, `cli`. Правка сразу в нескольких местах — `repo`.
- В заголовке просится «и» или перечисление — это два коммита.
- Тело необязательно. Пишем в нём причину и последствия, а не пересказ диффа.
- Формат проверяет хук `commit-msg`; обходить его (`--no-verify`) нельзя.

## Код и комментарии

- Идентификаторы — английские, тексты, комментарии, документы — русские.
- Комментарий объясняет, почему код такой, а не что он делает. Без истории правок, без мёртвого кода и TODO без условия.
- Любую строку своего кода участник должен уметь объяснить на защите.

## Что менять только вместе

Общий контракт — `app/contracts/`, `migrations/`, `config/factors.yaml`, `config/okved_sectors.yaml`, формы API (`docs/openapi.json`). Добавить поле или значение можно своим PR с одобрением владельцев затронутых ролей; переименовать или удалить — только вместе всеми. Задача трогает контракт — остановитесь и скажите об этом в PR.

Все вызовы LLM идут через шлюз роли 1, компания и роль пользователя берутся только из сессии: у граничных функций и инструментов агента нет параметра `company_id`, это проверяет `tests/boundary/test_isolation.py`.

## Проверки перед PR

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest -rs                # с TEST_DATABASE_URL: тесты с БД не должны пропускаться
uv run orientir openapi --check  # docs/openapi.json совпадает с кодом; устарел — `uv run orientir openapi`
npm --prefix web run build       # если менялся веб
```

`make test` запускает первые три. Правка промпта или весов — ещё `make eval` на разработочном окне. Что не запускалось, в описании PR так и пишем.

В теле PR: что и зачем, как проверено (команды и результат), что осталось, ссылка на спеку и пункт ТЗ.
